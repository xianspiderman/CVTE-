# SCM AI 助手

## 调用与复用

`AiPanel → AiController → AiChatService → LangChain4j → 公司 Responses API`。模型返回结构化函数请求后，Java 校验工具名和参数，调用既有业务服务，并通过同一工具调用 ID 把执行结果发回模型。对话按会话保留最近 4 轮，空闲 30 分钟后过期。每轮最多请求模型 4 次、执行工具 6 次。

| 任务书工具                  | 用途与数据来源                                                                                                                                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_todo_summary`          | 按负责人、业务、来源、创建时间范围汇总待办总数、今日新增、今日到期、逾期、高风险，调用 `MetricService.summary`。                                                                                           |
| `search_todos`              | 复用 `TodoReadService.page`，支持视图、状态、风险、来源、业务、负责人、关键词、创建时间范围与分页，每页 10 条。                                                                                            |
| `get_metric`                | 复用 `MetricService` 计算指标和 7/30 天趋势。本周按时完成率用已有本周完成筛选与同一计算公式。OVERDUE_TREND 表示近 N 天到期且当前仍未完成的逾期记录，按到期日期分布；不使用创建日期，也不冒充历史每日存量。 |
| `get_system_link`           | 按任务 ID、精确单号或页面代码定位待办，调用 `LinkService.resolve`。页面匹配多条时展示最多 5 个候选入口，点击打开所选单据。                                                                                 |
| `update_workbench_config`   | 模型用 `propose_workbench_config` 预览单张卡片的位置、显示状态或名称。页面确认后由 Java 执行更新，复用 `ConfigService` 校验、保存和业务审计。                                                              |
| `generate_business_summary` | 从统一指标和待办服务获取依据，由模型归纳工作重点、工作摘要或拟写供应商催办话术。                                                                                                                           |

查询条件、统计值、单据、数据源和链接取自 Java 工具结果。来源元数据包括每个来源中已入库记录的最新业务更新时间，以及最近同步/导入尝试的时间和状态。来源失败、部分导入或尚未接入时，助手同时显示可能缺失或滞后的具体来源。没有可用工具结果时返回提示。模型生成的业务摘要以纯文本展示，链接按钮由已校验的业务地址生成。

## 配置确认

提案只能在生成它的会话中处理，有效期 5 分钟。一次只能处理一份提案，等待期间可确认或取消。确认时数据库锁定配置行，核对当前配置与生成提案时的快照。配置已变化时返回冲突，需要重新提案。确认保存与成功审计在同一事务内，处理后的提案 ID 无法重复使用。

## HTTP API

响应沿用 `{code,message,data}`，接口定义可在 `/v3/api-docs` 查看。

| 方法与路径                   | 输入与输出                                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| GET /api/ai/status           | 配置状态及模型 ID。配置就绪状态在本地检查，模型响应在对话时检查。                                                |
| POST /api/ai/chat            | `{sessionId?,message}`，首次省略会话 ID。返回会话 ID、回复、工具状态、结构化结果和可选提案。消息最多 2000 字符。 |
| POST /api/ai/config/decision | `{sessionId,proposalId,confirm}`，其中 `confirm` 为显式布尔值。返回结果及是否保存。                              |
| GET /api/ai/logs             | 最近 200 条 AI 工具与调用异常记录，展示执行状态、耗时和错误。                                                    |

非法参数返回 400，提案不匹配返回 404，忙碌和配置冲突返回 409，过期返回 410，模型调用异常返回 502，AI 未配置返回 503。AI 审计复用已有 `ai_tool_log` 表，记录参数字段名和状态，省略对话原文、实际参数值、业务数据和凭据。

## 复现

1. 使用独立本地数据库和三组空闲端口启动。按 README 注入公司模型配置。
2. 执行 `./scripts/verify.sh` 和 `python3 scripts/acceptance.py`，装入固定验收数据。
3. 执行 `python3 scripts/ai-acceptance.py`。脚本比对问答、组合筛选、追问、趋势和链接，检查配置确认、取消、重放、部分数据和审计。脚本用固定数据修改并恢复配置和 Mock 来源，应在隔离的本地验收实例运行。
4. 可另用 `SCM_AI_LIVE_TEST=true mvn -f backend/pom.xml -Dtest=CompanyModelTest test` 验证真实对话和随机工具值往返。该用例需要在进程环境中设置模型基址及 Key。

模型接入使用 LangChain4j 1.23.0 的 Responses 客户端。[LangChain4j OpenAI 集成说明](https://github.com/langchain4j/langchain4j/blob/main/docs/docs/integrations/language-models/open-ai.md)
