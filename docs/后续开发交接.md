## 已确认的问题

| 范围 | 源码行为与影响 |
| --- | --- |
| 导入尝试记录 | `ImportService.batches()` 只读最近 100 个已提交批次。解析失败或整笔事务回滚不会保留批次，主要靠来源状态和操作日志追查。上传失败时 `DataSources.upload()` 未刷新来源状态，失败审计再次出错还可能覆盖原异常。 |
| 导入结果语义 | `ImportService.ingest()` 有任一错误即标 `PARTIAL`，全错也如此。零行到达入库流程会标 `SUCCESS`。接入类型由文件名的 `HTTP:` 前缀推断。重复上传仍会解析、查库及写新批次，待办按来源键与更新时间保持幂等。 |
| 查询与统计 | `TodoReadService` 取 `TodoMapper.all()` 的整表联查结果，在 JVM 筛选和分页。指标多次遍历同一份行集合。工作台并行请求与 AI 摘要可能重复读全表，独立请求没有共同快照。 |
| 本地权限边界 | 后端和页面面向本地单用户 `demo`，没有登录、角色或数据权限。`MINE` 是演示筛选条件。`SourceService.validEndpoint()` 仅放行指定端口的 `http://127.0.0.1/...` Mock API，HTTP 适配器禁用自动重定向。AI 网关是独立的后端 HTTPS 配置。若考虑多人或外部来源，需先评审鉴权、数据隔离、访问及审计边界。 |

## 待验证风险与评审顺序

1. **先明确失败语义。** 评审全错、零行、失败尝试、错误详情与重试的期望，再处理日志保留及故障隔离。测试审计失败、事务回滚、重复上传和客户端超时。
2. **分别测量导入和查询。** `FileAdapter` 会保留完整 CSV 文本或 POI 工作簿，并构造行集合。5 MB 上传限制不能推导 XLSX 解压后的堆上限。有效行先查后写、同源事务锁持有时间较长。测接近 10,000 行、多列、全错及并发，再评审资源上限、事件读取和批量写入。用 `EXPLAIN`、SQL 次数和延迟评估待办 SQL 分页及聚合，先验证时区、过滤、指标与 AI 结果一致。
3. **保留数据库保护。** DDL 四条外键为待办、批次、模板到来源，以及错误到批次，默认限制有子记录时删除或修改引用键。暂未有证据支持删除外键。清理先评审保留期和依赖顺序。核对实际索引及历史空日期数据后再决定是否调整约束。
4. **按使用场景评审权限和数据源扩展。** 生产化之前先确认数据归属及访问模型。连接来源扩展、导入后台化、鉴权和持久层重构均是待评审方向，未在迁移中实施。
